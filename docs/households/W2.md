# Households wave 2: the invite loop

Job 169b, wave 2 of 3. Builds on wave 1 ([`W1.md`](W1.md)). Design source: [`PLAN.md`](PLAN.md)
section 4 and the HH2 parts F to I. Peter's calls (2026-11-08): reusable group links are OK
(30 days, 50 joins, revocable, admins only); admins can remove members, revoke the group link and
make a new one; invites stay links the user shares (N-18).

## Roles

- `owner`: whoever created the household (one per household). `admin`: named by the owner.
  `member`: everyone else.
- The owner names and un-names admins (`set_member_role`). Owner and admins remove members
  (`remove_member`); an admin can't remove the owner or another admin; nobody removes themselves
  (that is leaving).
- When the owner leaves or deletes their account, ownership passes to the earliest-joined admin,
  else the earliest-joined member (today's `delete_account` rule, now also on leave and removal).
- Any member creates person invites (as today). Group links: owner and admins only.

## Data

`invites` gains:

- `kind text not null default 'person' check (kind in ('person','group'))`
- `max_uses int not null default 1 check (max_uses between 1 and 50)`, `use_count int not null
  default 0`, `preview_count int not null default 0` (join page opens; a counter, no identities).
- Person: 7 days, one use (today). Group: 30 days, 50 uses. One active group link per household:
  creating one while another is active answers the active one (idempotent); revoke, then create
  makes a new code.

`invite_uses (invite_id, household_id, user_id, joined_at)`, primary key `(invite_id, user_id)`,
RLS `is_household_member(household_id)`, two-household case in `rls.test.sql`. Every accepted
invite (person or group) writes a row; the "joined" lists read it.

`household_removals (household_id, user_id, removed_at)`, primary key `(household_id, user_id)`,
RLS `is_household_member(household_id)` but no grant to clients (nothing in the app reads it),
written by `remove_member` only. `check_invite` refuses the removed user every invite of that
household made at or before `removed_at`, and every invite whose creator is not the household's
owner or an admin at check time (Q-HH3: removing is their call). A daily cron job
(`purge_household_removals`, 03:47) deletes records 30 days after `removed_at`, when every invite
made up to the removal has expired.

## Join page (`/join/<code>` on the web app's domain)

- Static HTML, CSS and a small module script in `app/web/join/` (no Flutter download first),
  served for `/join/*` by a `vercel.json` rewrite placed before the SPA rewrite; `e2e/serve.mjs`
  routes like `vercel.json` already. Universal links and App Links still open the installed app.
- It calls `preview_invite_public` with the publishable key and shows: "<Inviter> lädt dich zu
  „<Household>" ein", members and open items, "Premium gilt für alle im Haushalt" when true, the
  code. DE or EN from `navigator.language`.
- Primary "Im Browser beitreten": the Flutter app at `/?invite=<code>` (router `inviteIn` already
  reads `?invite=`), which runs today's join flow (sign-in keeps the code).
- "App laden" only once a store listing is public (Android: Play link with
  `&referrer=invite%3D<code>`; iPhone: App Store link plus a Smart App Banner
  `app-id=6826922741, app-argument=<join url>`), and "Code kopieren". Until the listings are
  public the page offers the browser join and the code.
- Invalid, full and rate-limited answers get their own short text and the browser-join fallback.
- Light and dark from `prefers-color-scheme`, the app's look (hex shapes, one 3D depth style).
- Same CSP as the app (`connect-src` already allows the project URL).

## App

- Invite sheet ("Leute einladen") reachable from the switcher row of every household and from
  the household page: person link (any member) and, for owner/admins, the group link with a QR
  code, uses ("12 von 50"), expiry, "Link widerrufen" and "Neuen Link erstellen", and "Wer ist
  beigetreten" (polled every 5 s while the panel is on screen and the app visible; `invite_uses` is not in realtime,
  whose DELETE events skip RLS).
- Share text by household kind (partner/family/flat/club/solo/none), DE and EN, always link plus
  code (N-18: the user shares it).
- Moment 5: "Premium gilt für alle im Haushalt" in the invite sheet when the household has Premium.
- Household page: members with role labels; owner/admin actions per member (remove with confirm,
  make admin / remove admin for the owner).
- Store bridges: Android reads the Play Install Referrer once on first launch (`invite=<code>`)
  into `PendingInvite`; the start screens offer "Einladung einfügen" which reads the clipboard
  only on that tap and accepts a join link or a bare code.
- Analytics: `invite_sent` gains `kind: person|group` and `context: switcher|household`;
  `invite_accepted.method` gains `referrer` and `paste`; new `member_removed` (no properties).
