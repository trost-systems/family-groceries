# Households wave 1: several households per user, the switcher

Job 169b, Phase 2, wave 1 of 3 (Peter, 2026-11-08: HH3 in waves; W1 multiple households +
switcher, W2 invite loop, W3 club features). Design source: [`PLAN.md`](PLAN.md) sections 2 and 3.
This file is the contract between the server (`supabase/`) and the app (`app/`). Change it first
when the contract changes.

Peter's calls that shape W1: Siri, Alexa and AI/MCP use a **default household the user picks**
(Q-HH4), with a sensible default (the first household). Premium stays per household (M-H1).

## Data

`household_members`:

- `unique (user_id)` dropped: a user can be in many households.
- `is_default boolean not null default false`, partial unique index `(user_id) where is_default`.
- A `before insert` trigger sets `is_default` when the user has no default yet (first membership).
- An `after delete` trigger promotes the user's oldest remaining membership (`joined_at`, then
  `household_id`, `limit 1 for update`) when the deleted row was the default. Every exit path
  (leave, removal, cascade from a deleted household, account deletion) goes through it.
- `role` check widens to `owner | admin | member` (W2 gives `admin` meaning; no behaviour yet).
- Select policy: a user's **own** rows are visible only where `is_default`; other members' rows of
  a shared household stay visible as today. This keeps old store builds (which read their own row
  with `.maybeSingle()`) at exactly one row. The new app never reads `household_members` directly.

`households`:

- `kind text null check (kind in ('partner','family','flat','club','solo'))` (shared with job 168,
  which asks "who do you shop with").
- `request_id uuid null`, unique `(created_by, request_id)`: idempotent create for new apps.

## RPCs (the app's interface)

| RPC | Answer | Notes |
| --- | --- | --- |
| `my_households()` | rows `id, name, kind, role, is_default, member_count, open_count, premium, joined_at`, ordered by `joined_at` | `open_count` = unchecked items. The switcher and session read this. |
| `household_members_of(p_household)` | rows `user_id, display_name, role, joined_at` | Security definer, membership-checked (`not_member` otherwise). Replaces direct `household_members` reads. |
| `set_default_household(p_household)` | void | `not_member` if not a member. |
| `create_household(p_name, p_default_stores, p_stores, p_request_id uuid, p_kind text)` | `{id, ...}` as today | With `p_request_id`: no `already_in_household` guard; the same request id returns the same household. More than 10 memberships raises `too_many_households`. Without `p_request_id` (old builds): exactly as today. The new household is the default only if it is the user's first. |
| `accept_invite(p_code, p_mode => 'add')` | `{status: 'joined'|'member', household_id}` | Adds a membership, leaves nothing. `member` when the invite's household is already one of the user's. Old signatures (`p_code`, `p_code + p_archive`) keep moving out of the **default** household only and make the joined one the default. |
| `leave_household(p_household, p_archive default false)` | `{status: 'left', deleted: bool, archived: bool}` | Leaves one household. Last member: deleted, or archived as today (`p_archive`, Lifetime, switch). |
| `leaves_unlocked(p_household default null)` | as today | Null = default household. |
| `create_personal_access_token(..., p_household default null)`, `create_api_token(..., p_household default null)` | as today | Bound to the given household (member check), else the default. |
| `preview_invite(p_code)` | as today | `leaves_unlocked` judged against the default (old join screen). New app ignores the move warning fields. |

Old signatures that act on the default membership only: `leave_current_household()`,
`leave_current_household(p_archive)`, `unarchive_household(p_household, p_archive)` (restores and
makes the restored household the default; the new app calls `unarchive_household(p_household,
p_archive, p_mode => 'add')`, which leaves nothing).

Single-row readers fixed to "given household, else the default": `feedback_before_insert` (keeps a
`household_id` the client sends when the user is a member), `export_my_data` (all households, under
`households`; `household` stays the default for the old shape), `delete_account` (every
membership).

## Integrations

- `householdOf()` (`supabase/functions/_shared/db.ts`) answers the user's **default** household.
  MCP over OAuth, Alexa and the Siri credential act there.
- Siri credentials follow the default at request time (they are per user and device, not per
  household); revoking on leave applies only when the user has no membership left.
- In-app dictation (`voice`, mode `parse`) sends `"household": <shown id>`; for the app's own
  session the function checks membership (`403 no_household` otherwise) and parses there, so the
  stores and categories it answers belong to that list. Without it, the default (older builds).
  Siri credentials and PATs ignore the field.
- PATs and API keys stay bound to the household they were created in.
- MCP: new tool `list_households` (name, member count, which is the default; not behind the
  Premium lock) and an optional `household` argument (id or name, case-insensitive) on the list
  tools; without it, the default.

## App

- Session: `InHousehold(userId, household, households)`; `household` is the one shown on this
  device: the last opened on this device if still a member, else the default.
- `SessionCubit`: `switchTo(id)`, `setDefault(id)`, `leave(id)`, `createHousehold(name, stores,
  kind)` (request id kept across retries; switches to the new household), `join(code)` (mode `add`;
  switches to the joined household).
- Device cache: current household per user plus the households list, lists cached per
  (user, household); no more dropping other households' lists.
- Switcher (PLAN S1): household name chip top left of the list, opening a sheet: one row per
  household (name, members, open items, check on the current one), then "Neuer Haushalt" and
  "Mit Code beitreten", footer "Siri, Alexa & KI nutzen: <default>" that opens the default picker.
  The chip carries only the name and an expand icon.
- Household page under More: name (rename), members, "Standard für Siri, Alexa & KI", leave (with
  confirm). Joining no longer warns that it moves the user.
- Analytics: `household_switched` (no properties), `household_created.context`
  (`onboarding | switcher`).
