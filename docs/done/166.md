# Job 166: the sync indicator follows the device's network

Peter (t651u), 2026-11-07: flight mode on or off showed or cleared „Offline“ only after the user
did something.

- **What.** `connectivity_plus` 7.3.2 (BSD-3-Clause) watches the OS network on the web, Android
  and iOS (`app/lib/app/network.dart`, `Network.up`/`down`). `main.dart` creates the watch, `App`
  provides it, and `ListScope` hands it to `ListCubit`, which feeds its existing `connection`
  state. There is no second banner or flag. Down shows „Offline“ at once. Once the network has
  been back for 1.5 s, the list subscribes the live channel again at once and retries (a resync
  and the queue), so the indicator goes without a tap. Flapping reconnects once. The error path
  and the 3 s retry stay as the fallback. Job 165's rules (Z104, the morph) are untouched. Linux
  has no watch. No new permission: Android's `ACCESS_NETWORK_STATE` was already merged in by
  Play Billing (manifest merge blame). iOS needs none. `internet_connection_checker_plus` is left
  out (it pings third-party hosts).
- **Tests.** `app/test/list/list_cubit_test.dart` group "the OS network (job 166)" (10 tests).
  `app/test/list/sync_indicator_test.dart` "the OS network going down opens the card with no
  tap ..." drives the real indicator. `app/test/app/network_test.dart` drives the plugin's
  channels. Mutants: ignoring the stream fails 4 cubit tests and the widget test; no debounce
  fails 2; no generation check, no backoff reset, no cancel on close and no initial check each
  fail their test.
- **e2e.** `e2e/tests/connectivity.spec.ts`: Playwright's offline mode fires the browser
  events. With nothing touched, „Offline“ shows within 3 s, and back online it clears on its own
  while the tick made offline reaches the server. CI run 42380982021: 44/44, with the spec
  4 times plus list-header and live-sync. With the stream ignored (probe branch, run 42380981760)
  it fails at "offline with no tap and no request".
- **Not proven here.** Flight mode on a real iPhone or Android phone. The runner has no device or
  emulator, so the native plugin is covered by its channel test and the CI iOS and Android
  builds.
