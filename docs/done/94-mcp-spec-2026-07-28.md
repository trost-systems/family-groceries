# Job 94: MCP protocol 2026-07-28 next to 2025-11-25, Client ID Metadata Documents

PR #231 (not merged, as the brief asks). Decisions: `docs/DECISIONS.md`, "Job 94". Guide:
`docs/MCP.md`, "Protocol 2026-07-28: Client ID Metadata Documents".

## What was built

- **Both protocol versions, pinned by tests.** The SDK (`@modelcontextprotocol/server` 2.3.1)
  already served 2026-07-28. `supabase/functions/mcp/protocol_test.ts` now pins each part of it
  through `handle()`:
  - 2026-07-28: `server/discover`, no `initialize` or sessions, `Mcp-Method`/`Mcp-Name` enforcement
    (400, `-32020`), the unknown-version error (`-32022`), `resultType` and the cache fields;
  - 2025-11-25 and older: `initialize`, `notifications/initialized`, stateless serving (GET and
    DELETE 405).

  `tools/list` and `server/discover` say `ttlMs: 3600000`, `cacheScope: private` (`tools.ts`).
- **Client ID Metadata Documents.** Supabase Auth 2.197 can't do CIMD, so the function runs a
  front at `<endpoint>/oauth`.
  - Files: `mcp/oauth.ts`, `mcp/cimd.ts`, `mcp/cimd_clients.ts`.
  - Database: migration `20261110190000_mcp_cimd_clients.sql`, which adds `oauth_cimd_clients`,
    `oauth_cimd_rate` and `oauth_cimd_rate_hit`.
  - Only 2026-era requests are pointed at the front; 2025 clients keep Supabase Auth.
  - Dynamic registration passes through.
  - The consent page shows the document's name and the host it came from.
  - Limits per host and in all, S256, and checked redirect URI schemes.
- **The probe** (`scripts/mcp-smoke.sh`):
  - In 2026-07-28 it hard-checks `server/discover`, the cache fields, the header enforcement and
    the unknown-version error.
  - `MCP_SMOKE_CIMD=1` and `MCP_SMOKE_CIMD_CLIENT` add the front's checks.
  - The fixture test has a breakage per check (28 tests).
  - The `site-agent` gate probes production in both versions.
  - `e2e/tests/mcp-smoke.spec.ts` probes the branch's server in both versions with CIMD on.
  - `scripts/smoke-remote.sh` probes both versions after every deploy, read-only
    (`MCP_SMOKE_CIMD=1`; no document goes through the hosted front).
- **Tests.**
  - `mcp/cimd_test.ts`, including Claude's, VS Code's and MCPJam's real documents.
  - `mcp/oauth_test.ts`.
  - `mcp/cimd_integration_test.ts` (db gate): the official MCP client in 2026-07-28 against the
    local Supabase Auth.
  - `supabase/tests/mcp_cimd_clients.test.sql`.
  - The Deno tests moved from 2025-06-18 to 2025-11-25.
- **verify-hummlist.** New journey `journeys/ai-consent-cimd.mjs`, plus updates to
  `features/ai-assistants.md` and its FEATURES-FOR-WRITERS section.

## Review 0 fixes (2026-11-04)

1. **Token limit per client also behind the proxy.** `clientAddress()` in `mcp/handler.ts` keys
   a proxied request (mcp.hummlist.com) on `x-vercel-forwarded-for`, which Vercel sets and a
   client can't forge there, and a direct one on `X-Real-IP`. Before, every client on the
   proxy would have shared Vercel's address. Tested in `handler_test.ts`.
2. **No production write from the smoke.** `smoke-remote.sh` runs 2026-07-28 with
   `MCP_SMOKE_CIMD=1` only: the flag, rediscovery and the refusal of an http client_id, none of
   which fetches or registers. `scripts/mcp-cimd-smoke-client.json` is gone. The one hosted
   proof is an optional step for Peter (NEEDS_PETER "Job 94").
3. **Notes in DECISIONS from the review's nice-to-haves.** Shared totals can be used up for an
   hour. Which secret key the admin API takes. The proxy address is unverified until the first
   2026 client.
