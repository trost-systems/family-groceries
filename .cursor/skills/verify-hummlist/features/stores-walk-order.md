# Stores, walk order and the sections of the list

The list is one scroll of sections: a divider per store that has open items, in the household's store order, then „Ohne Laden“ for items without a store. Each divider reads „<Store>, N Artikel“ and shows the store's full name in a small hexagonal pill with a cobalt line behind it (no logos, no retailer colours). Under it, small category dividers follow that store's own walking order (the order a person walks through that store), and the items in each category follow the household's item order. Nothing on the list drags (job 78): an item moves to another store or category in its edit sheet, and the order of stores and categories is changed under Liste → „Anpassen“, whose store details a hold or right click on a divider opens directly. Folded stores stay folded, and the household remembers which store each item was put in. Stores show no logos. A household adds its own stores in the add and edit sheets' store options („+ Neuer Laden“ / "+ New store": type a name, Enter, the store is created and picked) and under Liste → „Anpassen“ (job 78; before, Mehr → „Läden“), which also renames, reorders and deletes them.

## Sub-features

- `sw-sections` one divider per store that has at least one open item, in store order, then „Ohne Laden“ / "No store" last while it has items. An empty store shows no divider and no „0 Artikel“. The divider's accessible name is „<Store>, N Artikel“ / "<Store>, N items" (1: „1 Artikel“ / "1 item").
- `sw-category-dividers` inside a section, category dividers in that store's walking order; „Ohne Laden“ uses the household's route order (Liste → „Anpassen“ → „Ohne Laden“). The divider text is the category name without its leading emoji ("👶 Drogerie" reads „Drogerie“); the dividers are headings (level 2). An item still being classified sits under „Wird einsortiert …“ / "Sorting …" at the top of the section.
- `sw-rows` a row shows an emoji for the item, the quantity first, then the name ("2 l Milch"), and brand · properties below. No visible check box; for screen readers the row is a checkbox. A partner's fresh row is tinted honey, a ticked row mint. Accessible name: name, then brand · properties, then quantity, then „Neu“ for a partner's fresh item.
- `sw-default-order` researched walking orders for the three chains. A store named EDEKA, Lidl or dm (any case, from onboarding, the store options or Liste → „Anpassen“) becomes that chain with its order, unless the household has that chain already; every other store gets the route order. Lidl: Brot & Backwaren, Obst & Gemüse, Kühlregal, Fleisch/Wurst/Fisch, Vorrat & Konserven, Süßes & Snacks, Getränke, Tiefkühl, Haushalt, 👶 Drogerie, Sonstiges. Edeka: Obst & Gemüse, Brot & Backwaren, Fleisch/Wurst/Fisch, Kühlregal, Vorrat & Konserven, Süßes & Snacks, Tiefkühl, Getränke, Haushalt, 👶 Drogerie, Sonstiges. dm: 👶 Drogerie, Vorrat & Konserven, Süßes & Snacks, Haushalt, Getränke, Sonstiges, then (hidden flag, still shown on the list when an item is there) Obst & Gemüse, Brot & Backwaren, Kühlregal, Fleisch/Wurst/Fisch, Tiefkühl.
- `sw-where-stores-come-from` a new household picks its stores at creation (feature onboarding, `create`): any of EDEKA, REWE, Lidl, Aldi Süd, Aldi Nord, Kaufland, Netto, Penny, dm, Rossmann, nothing preselected, plus own ones; „Überspringen“ / "Skip" starts with none (the list has only „Ohne Laden“). EDEKA, Lidl and dm get the layouts above, the others the route order. Households made before job 58 kept dm, Lidl and Edeka. Stores can be added later (`sw-own-stores`). The store-name note „Ladennamen wie dm, Lidl oder EDEKA verwenden wir nur, …“ / "We use shop names such as dm, Lidl or EDEKA only, …" stands only on the onboarding store step (job 78 removed it from the stores screen).
- `sw-no-drag` nothing on the list drags: a hold on a row opens its edit sheet as soon as the hold completes (about 300 ms), and moving the pointer afterwards moves nothing; empty stores never show as drop targets. An item changes store or category only in the edit sheet (feature edit-item) or the add sheet.
- `sw-own-stores` own stores: „+ Neuer Laden“ / "+ New store" (accessible name „Neuen Laden anlegen“ / "Add a new store") ends the store options of the add sheet and the edit sheet; it turns into a field „Name des Ladens“ / "Store name" with a check („Laden anlegen“ / "Add store") and a close button. Enter or the check creates the store and picks it (announced „Rewe angelegt und ausgewählt“ / "Rewe added and selected"); Escape cancels. A name the household has, in any case, picks that store. Over five stores a search field „Läden durchsuchen“ / "Search stores" filters the options („Ohne Laden“ hides while a query is typed); Enter there picks the store of that name or opens the new-store field with the text. Liste → „Anpassen“ adds („Laden hinzufügen“ / "Add store" bottom right: a dialog of that title with the field „Name des Ladens“ / "Store name" and „Laden anlegen“; a name the household has adds nothing; refused or offline the dialog stays open), renames (on the store's details, the pill on top, button „<Store> umbenennen“ / "Rename <Store>": the same dialog prefilled, „Speichern“ / "Save"; a name another store has keeps the dialog open with „Einen Laden „Lidl“ gibt es schon.“ / "A store named “Lidl” already exists.") and deletes (the row's trash, tooltip „<Store> löschen“ / "Delete <Store>": the dialog „<Store> löschen?“ names the open items that move, e.g. „1 offener Artikel kommt zu „Ohne Laden“. Sein Laufweg geht mit.“, buttons „Abbrechen“ and „Löschen“ / "Delete"; its items, open and bought, have no store afterwards). Renaming dm, Lidl or EDEKA to another name ends the chain: dm's brand guesses no longer pick it. Names: at most 40 characters, unique ignoring case and spacing. A new store's walking order is the chain's (`sw-default-order`) or else the household's route order with every category. Adding, renaming and deleting need a connection: offline the snackbar says „Läden lassen sich nur mit Verbindung anlegen, umbenennen oder löschen.“ / "Adding, renaming or deleting stores needs a connection." `e2e/tests/stores-add.spec.ts`.
- `sw-store-order` the order of the stores is changed on the stores screen under Liste → „Anpassen“ (job 78), not on the list.
- `sw-category-order` a store's category order is changed in that store's details in Anpassen; for „Ohne Laden“ that is the household's route order. Not on the list.
- `sw-divider-hold` a hold (about 300 ms) or a right click on a store divider opens that store's details in Anpassen (path `/edit/<store id>`); on „Ohne Laden“ the details of the section without a store (`/edit/none`), its categories. A category divider opens the details of the store whose section it is in. The divider moves nothing and has no menu and no up/down moves; a screen reader's long-press action on a divider does the same.
- `sw-layout-screen` a store's details (job 78, route `/edit/<id>`; from Liste → „Anpassen“ → the store, or a hold or right click on its divider (`sw-divider-hold`)): title = the store's name; on top the store's badge with „Tippen zum Umbenennen“ / "Tap to rename" (`sw-own-stores`); the hint „Ordne die Kategorien so, wie du durch den Laden gehst. Tippe auf eine Kategorie, um sie umzubenennen.“ / "Order the categories the way you walk through the store. Tap a category to rename it."; every category has its step number, a trash (not „Sonstiges“) and a drag handle „<Kategorie> verschieben“ / "Move <category>"; „Kategorie hinzufügen“ bottom right (feature categories). Each change saves at once and shows on the list. A store deleted on another device sends the screen back to „Läden“.
- `sw-more-stores` (id kept; job 78 moved it to the List tab) the list header's „Anpassen“ / "Edit" (top right, the button's name is exactly that) opens „Läden“ / "Stores" (route `/edit`, the tabs stay; back returns to the list): hint „Ziehe die Läden in die Reihenfolge, in der sie auf der Liste stehen. Tippe auf einen Laden, um ihn umzubenennen und seine Kategorien zu ordnen.“ (EN: "Drag the stores into the order they have on the list. Tap a store to rename it and order its categories."). One row per store (a button named by the store, its badge), a trash „<Store> löschen“ / "Delete <Store>" and a handle „<Store> verschieben“ / "Move <store>". A tap on a row opens its details (`sw-layout-screen`); a drag on the handle reorders the stores. Last, pinned where its section sits on the list: „Ohne Laden“ / "No store", flat and muted with „Kategorien für Artikel ohne Laden“, no trash, no handle; it opens the route order (feature categories). Bottom right „Laden hinzufügen“ / "Add store" (`sw-own-stores`). Without stores the hint reads „Noch keine Läden. Leg einen an, dann sortiert die Liste deine Artikel nach seinem Laufweg.“ / "No stores yet. Add one and the list sorts your items along its walking route." Mehr has no „Läden“ row since job 78.
- `sw-fold` a tap on a store divider (including „Ohne Laden“) folds or unfolds its section; folds are remembered on the device and survive a restart. A screen reader hears the hint „Zuklappen“ / "Collapse" (open) or „Aufklappen“ / "Expand" (folded).
- `sw-explainer` a card above the list: „Tippen hakt ab · Halten bearbeitet“ / "Tap ticks off · Hold to edit", with the button „Verstanden“ / "Got it". Dismissed for good on that device.
- `sw-store-memory` the household remembers an item's store: when an item's store is set in the edit sheet or add sheet chip, or ticked while it has a store, a later add of the same item (also from MCP/Siri/Alexa) lands in that store. Choosing „Ohne Laden“ for an item clears the memory. Ticking an item without a store remembers nothing. The add sheet also guesses dm for drugstore items and a brand's own store.
- `sw-columns` on wide screens (width at least 840 px: two columns, 1200 px: three) the sections flow into columns of whole sections.
- `sw-live` a partner's moves, adds and order changes show on the other client without a reload.

## How to get to it (user POV)

- Open the app on the „Liste“ tab: each store is a section with its own divider.
- Tap the divider to fold; hold it, or right click it, to open its store's details in Anpassen.
- Hold a category divider, or right click it, for the same store's details.
- Hold an item (or right click it) to edit it; its store and category chips move it.
- On the list, tap „Anpassen“ top right; tap a store for its details.
- Tap „Verstanden“ on the card above the list.

## Driving it with Playwright

Preconditions:

- Seeded household „Familie Brandt“ signed in on the list tab. It has no stores: add dm, Lidl and Edeka in that order first, as in `README.md` (Baseline), since the steps below read their walk orders (list state from `sectionHeadings`/`outline` in `e2e/tests/catalog.ts`). Or sign up fresh with `signUpWithHousehold(page, newEmail('x'), { stores: chainStores })` (`e2e/tests/helpers.ts`).
- Items to sort come from `addItem`/`enterItem` (add sheet) or direct API inserts as `seed` in `e2e/tests/list-walk-order.spec.ts`.

- **Read the sections.** `storeDivider(page, 'Lidl')` = button named `^Lidl, \d+ Artikel`. `outline(page)` from `e2e/tests/catalog.ts` returns each section's store, headings and items. Observable: store order, headings per section (`page.getByRole('heading', { level: 2 })`).
- **Move an item to a store.** `setStore(page, 'Brot', 'Lidl')` (`e2e/tests/catalog.ts`: edit sheet, chip „Laden“, „Fertig“). Observable: `storeOf(page, 'Brot')` becomes `Lidl`, divider count changes to „Lidl, N Artikel“. `setCategory` does the same for a category.
- **Nothing drags.** Hold a row with the mouse 700 ms: the edit sheet shows while the button is down; move and let go: `outline(page)` is unchanged. Spec: the "nothing on the list drags" test in `list-walk-order.spec.ts`.
- **Divider hold.** `storeDivider(page, 'dm').click({ button: 'right' })` (or a 700 ms hold): `expect(page).toHaveURL(/\/edit\/[^/]+$/)` and the heading „dm“ shows.
- **Open a store's details.** `openStoreDetails(page, 'Edeka')` (Liste, „Anpassen“, the Edeka row): `page.getByRole('heading', { name: 'Edeka', exact: true })` visible. Reorder with `dragHandle(page, 'Kühlregal verschieben', 'Obst & Gemüse verschieben')`, then `openTab(page, 'Liste')`: `sectionHeadings(page, 'Edeka')` shows the new order and survives `page.reload()`.
- **Stores screen.** `openStores(page)` (`e2e/tests/catalog.ts`: `getByRole('button', { name: 'Anpassen', exact: true })`); rows `storeRow(page, '<Store>')` (button named exactly the store), handles „<Store> verschieben“, trash „<Store> löschen“, `storeRow(page, null)` for „Ohne Laden“. A tap on a row opens its details.
- **Own store.** In the add sheet, `page.getByRole('button', { name: /^Laden: / })`, then `getByRole('button', { name: 'Neuen Laden anlegen' })`, `typeInto(getByRole('textbox', { name: 'Name des Ladens' }), 'Rewe')`, Enter: the chip reads „Laden: Rewe“ and the item lands under a Rewe divider. On Rewe's details (`openStoreDetails(page, 'Rewe')`): button `'Rewe umbenennen'`, type „Rewe Markt“ into „Name des Ladens“, Enter; „Zurück“; then button `'Rewe Markt löschen'`, the dialog text, `getByRole('button', { name: 'Löschen', exact: true })`: the item sits under „Ohne Laden“. Spec: `e2e/tests/stores-add.spec.ts`.
- **Fold.** `storeDivider(page, 'dm').click()`; the items of dm disappear; after `page.reload()` they are still hidden. Click again to unfold.
- **Explainer.** On a fresh account the card text is visible; `page.getByRole('button', { name: 'Verstanden' }).click()` removes it for good.
- **Store memory.** `setStore(page, 'Hack', 'Edeka')`, `tick(page, 'Hack')`, `addItem(page, 'Hack')`: it lands under Edeka.
- **Specs.** `e2e/tests/stores.spec.ts` (ordering per store, layout screen, memory, live sync), `e2e/tests/list-walk-order.spec.ts` (dividers, folds, explainer, nothing drags, wide columns), `e2e/tests/list-header.spec.ts`. Run with `scripts/verify.sh --only e2e -- tests/stores.spec.ts`.

## Gotchas

- A hold fires while the pointer is still down (about 300 ms; on web 100 ms after the engine's 200 ms click debounce). A finger may drift up to 18 px and still hold; further, the press scrolls instead.
- `getByText` for a store name can also hit the edit sheet's store options behind or in a sheet; use `storeDivider`.
- The store names dm, Lidl, Edeka are chains the household adds; seeded households and test accounts created with „Überspringen“ have no store. Add one with Liste → „Anpassen“ → „Laden hinzufügen“ or `db.rpc('add_store', { p_household, p_name })` (`e2e/tests/mcp.spec.ts`).
- The store badge is the store's full name in a hexagonal pill (long names end in „…“), the same on dividers, under Liste → „Anpassen“ and in the add sheet. Since job 57 (2026-11-01) there are no letter squares and no retailer colours (Legal N-23); logos would need a Legal Review and none ship. It is decorative: the accessible name is just the text („<Store>, N Artikel“).
- A category change in the edit sheet teaches the household (`category_memory`). Do not use the baseline household for such tests if its learned categories matter.
- Hidden flags for dm's food categories are stored but change nothing on the list: an item in Obst & Gemüse tagged to dm still shows. unverified (no UI to set hidden; read from code only).
- Fold state and the dismissed explainer are per device (browser storage); a fresh browser context shows the card again.
- The e2e build turns on some flags (see the app config); store behaviour is the same in both builds.
- A hold on „Ohne Laden“ opens `/edit/none`, the categories of the section without a store.
