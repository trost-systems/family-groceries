# Household and invites

One household shares one list, and a person can be in several households (job 169b; up to 10). The household's name is the chip top left of the list, and appears on the join screen, in the account deletion dialog and on the AI-assistant consent page (there the default household). A member invites a partner with an 8-character code and a link (valid 7 days, usable by one person), shares or copies them, and can revoke open invites. A person joins by typing the code or opening the link; joining adds the household and keeps the others. The household page under More renames it, lists its members, makes it the default for Siri, Alexa & KI, and leaves it.

## Sub-features

- `invite-create` More → „Partner einladen“ / "Invite your partner" (title „Einladungen“ / "Invites"): text „Teile den Link oder den Code mit der Person, mit der du einkaufst. Die Einladung gilt 7 Tage und für eine Person.“ / "Share the link or the code with the person you shop with. The invite is valid for 7 days and for one person." Button „Neue Einladung“ / "New invite". In the phone apps the share sheet opens as soon as the invite exists; on the web the card appears and you share or copy from it.
- `invite-card` per invite: „Code“ with the 8 characters (letters A-Z and digits 2-9, no I, O, 0, 1), „Link“ (`<app origin>/join/<code>`; on the phones https://app.hummlist.com/join/<code>), „gültig bis {date}, {time} Uhr“ / "valid until {date}, {time}", buttons „Teilen“ / "Share" (only where a share sheet exists: phones, browsers with Web Share), „Link kopieren“ / "Copy link" (snackbar „Link kopiert“ / "Link copied"), „Code kopieren“ / "Copy code" (snackbar „Code kopiert“ / "Code copied"), „Widerrufen“ / "Revoke" (accessible name „Einladung {code} widerrufen“ / "Revoke invite {code}"). The card on onboarding Step 3 has no „Widerrufen“; revoking happens on „Einladungen“.
- `share-text` the share sheet text: „Komm in unseren Hummlist-Haushalt: {link} · Code: {code}“ / "Join our Hummlist household: {link} · Code: {code}" (code only when the build has no app URL).
- `open-invites` list „Offene Einladungen“ / "Open invites"; empty: „Keine offenen Einladungen.“ / "No open invites." Used, revoked and expired invites are not listed. Any member can revoke any open invite; its card goes, without a snackbar. A create or revoke that fails (for example offline) leaves the cards as they are and shows the reason as text under „Neue Einladung“.
- `expiry-single-use` an invite is valid 7 days from creation (database default) and works once; after use, revoke or expiry the code gives „Dieser Code ist ungültig oder abgelaufen.“ / "This code is invalid or has expired." (one answer for made-up, expired, revoked and used codes).
- `join` More → „Anderem Haushalt beitreten“ / "Join another household", onboarding „Einladung annehmen“ or an invite link. The title depends on membership, not on the way in: „Einladung annehmen“ / "Join with an invite" without a household, „Haushalt beitreten“ / "Join a household" in one (driven 2026-11-04): field „Einladungscode“ / "Invite code" (upper-cased, spaces and dashes ignored), „Weiter“ / "Continue" previews the household under „Einladung in den Haushalt“ / "Invite to the household", then „Haushalt beitreten“ / "Join household" or „Abbrechen“ / "Cancel". Opened from More, back and „Abbrechen“ return to More (job 78, 2026-11-02; before, to the list); from onboarding, to Step 1; from an invite link while in a household, to the list.
- `switcher` (job 169b) the chip top left of the list shows the shown household's name and an expand icon; it opens a sheet „Deine Haushalte“ / "Your households": a row per household (name, „2 Mitglieder · 4 offen“ / "2 members · 4 open", a check on the one shown), „Neuer Haushalt“ / "New household", „Mit Code beitreten“ / "Join with a code", and „Siri, Alexa & KI nutzen: {name}“ / "Siri, Alexa & AI use: {name}", which opens „Standard für Siri, Alexa & KI“ / "Default for Siri, Alexa & AI" to pick another. The chip shows with one household too.
- `household-page` (job 169b) More → the household's name: „Haushalt“ / "Household" with „Name des Haushalts“ and „Umbenennen“ / "Rename", „Mitglieder“ / "Members" („Peter (du)“ / "Peter (you)"), „Als Standard nutzen“ / "Make default" or „Siri, Alexa und KI-Assistenten nutzen diesen Haushalt.“, and „Haushalt verlassen“ / "Leave household" with a confirm dialog „„{household}“ verlassen?“ (others keep the list; the last member deletes it; with Lifetime the warning or, with the archive on, „Archivieren und verlassen“ / „Löschen und verlassen“). The dialog reads the members when it opens, not when the page did: if the others left meanwhile it says the household is deleted. Once left, the household is gone from the app even when the reload after it fails.
- `join-adds` (job 169b) joining while in a household no longer warns or leaves anything: the joined household is added and shown. A code or link of a household the user is already in shows that household (no join, the invite stays unused).
- `link-join` opening `/join/<code>` signed in goes to the join screen with the code previewed; signed out, the address becomes `/login?invite=<code>` and the code survives sign-in, the analytics question and onboarding (kept 7 days; without a household Step 1 is skipped). A member opening their own household's link lands on the list.
- `rate-limit` 10 failed codes within an hour block even valid codes: „Zu viele Versuche. Bitte später noch einmal.“ / "Too many attempts. Please try again later."
- `premium-on-join` the join screen mentions Hummlist Lifetime when the target has it (since job 169b nothing is left, so no warning about the old household). Premium is not on sale yet (hold `premium-launch`), so a normal user sees none of this.
- `archive` „Archivierte Haushalte“ / "Archived households" in More and „Archivieren und verlassen“ / "Archive and leave" on the household page: off in production (see Gotchas).

## How to get to it (user POV)

- Right after creating a household: Step 3 „Partner einladen“ (see onboarding).
- Later: tab „Mehr“ / "More", row „Partner einladen“ / "Invite your partner" (second group, one line; since job 85 no section heading and no household name), page „Einladungen“.
- Joining: row „Anderem Haushalt beitreten“ in the same section; or an invite link; or at first run „Einladung annehmen“.
- Household name: the chip on the list; renamed on the household page (More → the household's name). Switching: tap the chip.

## Driving it with Playwright

Preconditions:

- The skill's release web build (`helpers/launch.sh`; no HOUSEHOLD_ARCHIVE). The baseline household „Familie Brandt“ has three members (Mia, Noah, Ida), so most join recipes use a fresh sign-up or an invite made in the app (`createInviteCode(page)` in `e2e/tests/helpers.ts`; `householdWithInvite` is local to `onboarding.spec.ts`).

- **Open the invite page.** `openMore(page, 'Partner einladen')`. Observable result: URL `/more/invites`, button „Neue Einladung“ visible.
- **Create an invite.** `page.getByRole('button', { name: 'Neue Einladung' }).click()`. Observable result: `inviteCodeLabel(page)` (the card's text starts `Code ABCD2345`, then the link and „gültig bis …“; driven 2026-11-06), text matching `/^gültig bis /`; read codes with `shownInviteCodes(page)`; the code matches `/^[A-HJ-NP-Z2-9]{8}$/`.
- **Copy.** `page.getByRole('button', { name: 'Link kopieren' }).click()` then `page.locator('[id^="flt-semantic-node-"]').getByText('Link kopiert', { exact: true })` (a plain snackbar, no action; as `onboarding.spec.ts` does); clipboard equals `<origin>/join/<code>` (needs clipboard permissions). Same with „Code kopieren“.
- **Revoke.** `page.getByRole('button', { name: 'Einladung ' + code + ' widerrufen' }).click()`. Observable result: the code's group gone, no snackbar (`page.getByText(/Link und Code/)` count 0); a second user opening `/join/<code>` sees „Dieser Code ist ungültig oder abgelaufen.“.
- **Join by code.** `openMore(page, 'Anderem Haushalt beitreten')`, then `joinWithCode(page, code, 'Haushaltsname')`. Observable result: URL `/`, the list of the new household; since job 169b the old household is kept (API: `my_households()`).
- **Switch** (job 169b, not driven yet). Click the household chip (its accessible name is the household's name), then the other household's row in „Deine Haushalte“.
- **Expiry and single use.** Use the API to backdate or use an invite (`adminClient()` in helpers); the specs check 6-day-old works, 7+ days fails.
- Covered by `e2e/tests/onboarding.spec.ts` (AC1-3, AC5-13, "a used invite disappears from More's invite list", link twice, race for one code), `e2e/tests/household-bound.spec.ts` (joining a household with Lifetime, archive; relies on the e2e-only `HOUSEHOLD_ARCHIVE` and `LEGAL_DRAFTS` defines), `e2e/tests/partner-news.spec.ts` (items the partner added are marked new until seen), `e2e/tests/live-sync.spec.ts` (AC4: joining by link and from More). Run via `scripts/verify.sh --only e2e -- tests/onboarding.spec.ts`.

## Gotchas

- `HOUSEHOLD_ARCHIVE` is not set in `app/config/auth.json` (the production web and store builds), so it is off for normal users: no „Archivierte Haushalte“ row, and the last member of a household with Lifetime leaving it sees the Lifetime-ends warning, not the archive offer. The e2e build turns it on; `household-bound.spec.ts` therefore shows behaviour users do not see. Peter's decision log says turning it on needs Legal Review first.
- Premium/Lifetime texts on the join screen are only reachable with a household that has a purchase; Premium is not on sale (hold `premium-launch`).
- Since job 169b the household page has the members list, rename and „Haushalt verlassen“; there is still no remove-member (wave 3). The household is deleted when its last member leaves. `e2e/tests/live-sync.spec.ts`, `onboarding.spec.ts` and `household-bound.spec.ts` still expect the old move-on-join screens until the job 169b e2e update.
- Siri, Alexa and AI assistants over OAuth act in the default household, not the one shown; API keys and access tokens are bound to the household shown when they were made.
- Headless Chromium has no Web Share, so „Teilen“ is absent in Playwright (driven 2026-11-04).
- Revoking is not undoable; there is no "revoke all".
- The invite link host: on the web it is the page's own origin, on the phones https://app.hummlist.com. The share sheet text uses the German or English variant of the app's language.
- Codes are compared upper-cased with other characters ignored; they never go to analytics.
- 7-day expiry and single use are in the database (invite default `now() + interval '7 days'`, `used_at` set on join); the pending invite on a device also lasts 7 days.
