# AI assistants (MCP) and access keys

An AI assistant such as Claude can read and change the household's shopping list through Hummlist's MCP server. The user connects it in one of two ways: signing in (OAuth) when the assistant asks, which opens a consent page „Zugriff erlauben?“; or with a personal access key that the user creates in the app (shown once). Everything is managed in Mehr → Zugänge: the server address with a copy button, the access keys, and the connected apps, each of which can be revoked or disconnected at once. Nothing needs Premium today.

## Sub-features

- `ai-url` the server address on Zugänge under „MCP-Server“ with a copy button (tooltip „Kopieren“, then „Kopiert“): `https://mcp.hummlist.com` in production builds.
- `ai-consent` the page an assistant opens to connect: „Zugriff erlauben?“ with „Angemeldet als <email>“, „Haushalt: <name>“, „<App> möchte:“ and what that includes; buttons „Erlauben“ and „Ablehnen“. A signed-out user signs in on the way and lands back on it. After a decision the page turns into „Verbunden“ with „Fertig, du kannst zu <App> zurückkehren.“ (EN "Connected", "Done, you can return to <App>.") or „Nicht verbunden“ with „Abgelehnt, du kannst zu <App> zurückkehren.“, and stays until the assistant's own page loads (Claude takes up to about 10 s). A client approved before skips the question: „Verbunden“ with „Fertig, du kannst zu deiner App zurückkehren.“ (EN "Done, you can return to your app."). An unknown or expired request shows the title „Verbindung abgelaufen“ (EN "Connection expired") and the button „Zurück zur Liste“ (EN "Back to the list").
- `ai-key-create` „Token erstellen“: name it, the key (`fgp_…`) is shown once, „Fertig“ closes it.
- `ai-key-list` keys list as „<Name>“ with „…<letzte 4> · Erstellt am <Datum> · Noch nie benutzt“ (or „Zuletzt benutzt <Datum>“).
- `ai-key-revoke` revoke a key: „<Name> widerrufen“ then „Widerrufen“; the next request with it is refused.
- `ai-key-limit` at most 20 active keys: „Höchstens 20 aktive Tokens.“
- `ai-key-retention` a key that has ended (revoked, or its owner left the household, or an automatic Siri key whose sign-in ended) disappears from the list at once and the stored record of it is deleted 30 days later by a daily clean-up. Leaving a household ends the keys made for it for good (rejoining does not bring them back).
- `ai-apps` „Verbundene Apps“ lists each approved assistant with the device it was approved on, the date and its last activity: „Chrome · macOS · Verbunden am <Datum> · Zuletzt aktiv <Datum>“ (EN "Chrome · macOS · Connected <date> · Last active <date>"). The device (job 80) is the browser and system of the consent page („Safari · iOS“, „Firefox · Linux“; in a phone app just „iOS“), missing for apps connected before job 80; „Zuletzt aktiv“ is the app's newest token refresh (about hourly while in use), missing before its first. The granted scopes are no longer listed. Empty state „Noch keine App verbunden.“
- `ai-app-details` (job 80) a tap on an app row opens a sheet: the name, „Freigegeben auf <Gerät>“, „Verbunden am <Datum>“, „Zuletzt aktiv <Datum>“ or „Noch nicht aktiv“, the heading „WAS <APP> DARF“ and in plain words: the list access (the consent page's sentence), „Deine E-Mail-Adresse sehen.“ (scope email), „Deinen Namen sehen.“ (profile), „Deine Telefonnummer sehen.“ (phone), „Verbunden bleiben, bis du die Verbindung trennst.“ (offline_access); EN "Approved on …", "Not active yet", "WHAT <APP> CAN DO", "See your email address.", "Stay connected until you disconnect it." Then the button „<App> trennen“ (key `app-details-disconnect`), which asks like the row's button and closes the sheet once disconnected. Keys: `app-<client id>` (row), `app-details` (sheet).
- `ai-disconnect` „<App> trennen“, confirm „Trennen“: access ends at once, also the refresh token.
- `api-section` (job 73, behind the PostHog flag `public-api`, off): a section „API“ (EN "API") below „Zugriffstoken“ with the base URL (`<project URL>/functions/v1/api/v1`) and a copy button, the text „Für eigene Skripte und Automationen: Lies und ändere eure Liste über HTTP, mit einem API-Schlüssel.“ (EN "For your own scripts and automations: read and change your list over HTTP with an API key."), a link „API-Dokumentation“ (EN "API documentation", docs/API.md on GitHub, new tab), the keys or „Kein aktiver API-Schlüssel.“ (EN "No active API key.") and the button „API-Schlüssel erstellen“ (EN "Create API key"). With the flag off the section shows only when the user has API keys, with just the heading and the keys, so they can still be revoked. Keys: `api-section` (the heading), `api-url`, `api-docs`, `api-key-tile`, `api-create`.
- `api-key-create` the dialog „API-Schlüssel erstellen“: field „Name“ (hint „z. B. Home Assistant“, at most 60 characters) and a choice „Nur lesen“ (default, „Liest die Liste, Kategorien und Läden. Ändert nichts.“) or „Lesen und schreiben“ („Kann auch Einträge hinzufügen, abhaken und verschieben.“); EN "Read only", "Read and write". Keys `api-scope-read`, `api-scope-write`. „Erstellen“ shows „API-Schlüssel erstellt“ with „Kopiere den Schlüssel jetzt. Er wird nicht noch einmal angezeigt.“ (EN "API key created", "Copy the key now. It won't be shown again.") and the `fgp_…` key once.
- `api-key-list` each key as „<Name>“ with „…<letzte 4> · Nur lesen“ or „· Lesen und schreiben“, „· Erstellt am <Datum> · Noch nie benutzt“ (or „Zuletzt benutzt <Datum>“). API keys never show under „Zugriffstoken“, and MCP tokens never under „API“.
- `api-key-revoke` „<Name> widerrufen“ then „API-Schlüssel widerrufen?“ „Skripte, die ihn benutzen, verlieren sofort den Zugriff.“ and „Widerrufen“.
- `api-key-limit` at most 10 active API keys per member: „Höchstens 10 aktive API-Schlüssel. Widerrufe erst einen.“ (EN "At most 10 active API keys. Revoke one first."). Created outside the app's own sign-in the server refuses: „API-Schlüssel kannst du nur hier in der App erstellen, während du angemeldet bist.“ While the server switch `app_switches.public_api` is off (job 75, production's default) the server refuses every new key: „Die API ist noch nicht freigeschaltet.“ (EN "The API isn't available yet.").
- `ai-tools` what an assistant can do (six tools): show the open list (optionally one store or category) with brand and properties, plus how many items are open on the whole list and how many were ticked in the last 24 hours; add one or more items (the name is split into name, brand, properties, quantity; a count in front is the quantity („2 Gurken“); one at the end only when it is 1 to 20 after a known name („Gurken 3“), while „Büroklammern 100“ or „Windeln Größe 4“ keep the number in the name; categories and stores are filled in automatically; an item already on the list is reported, not duplicated; a similar one like „Karotten“ next to „Möhren“ is added and reported); tick items off (they move to „Zuletzt verwendet“); move an item to another category and/or store (the household remembers it); list categories; list stores. Changes show up in the app on all phones within seconds.

## How to get to it (user POV)

- Tab „Mehr“ / "More" → row „Zugänge“ / "Access" (its own group; no hint since job 85). The page has these headings in German: „MCP-Server“, (on iPhone builds also „Siri“, see the siri map), „Zugriffstoken“, „Verbundene Apps“. English: "MCP server", "Access tokens", "Connected apps" (empty: "No apps connected yet.").
- Text under „MCP-Server“: „Für Claude, ChatGPT und andere KI-Assistenten. Verbinde per Anmeldung (OAuth) oder mit einem Zugriffstoken.“ / "For Claude, ChatGPT and other AI assistants. Connect by signing in (OAuth) or with an access token."
- Under „Zugriffstoken“ (job 80, key `access-tokens-hint`): „Mit einem Token baust du eigene Automationen, die eure Liste pflegen, etwa ein Skript oder einen Assistenten am MCP-Server.“ (EN "Use a token to build your own automations that manage your list, like a script or an assistant on the MCP server."); while the `public-api` flag shows the API section instead „Mit einem Token baust du eigene Automationen am MCP-Server, die eure Liste pflegen. Für Programme ohne MCP gibt es unten die API.“ (EN "Use a token to build your own automations on the MCP server that manage your list. For programs without MCP, use the API below.")
- „Zugriffstoken“ empty state „Kein aktiver Token.“ / "No active token."; create dialog „Token erstellen“ with field „Name“ (hint „z. B. Claude oder Kurzbefehle“), buttons „Abbrechen“ / „Erstellen“; result dialog „Token erstellt“: „Kopiere den Token jetzt. Er wird nicht noch einmal angezeigt.“ / "Copy the token now. It won't be shown again."
- Revoke dialog „Token widerrufen?“: „Apps, die ihn benutzen, verlieren sofort den Zugriff.“ Disconnect dialog „<App> trennen?“: „Die App verliert sofort den Zugriff auf deine Liste.“
- Consent page lines: „<App> möchte:“ then „Einträge deiner Einkaufsliste lesen, hinzufügen, abhaken und verschieben. <App> und sein Anbieter erhalten dabei die Inhalte eurer Liste.“ (EN "Read, add, tick off and move items on your shopping list. <App> and its provider will receive your list contents."); invalid link: „Diese Anfrage ist ungültig oder abgelaufen. Starte die Verbindung in deiner App neu.“
- In the assistant (Claude): add a custom connector with the address; no client ID or secret. Tester guide: hummlist.com `/de/anleitungen/claude`, `/en/guides/claude`. Claude Code: `claude mcp add --transport http hummlist https://mcp.hummlist.com` (the guide's name; any name works), then `/mcp` → Authenticate. Codex (in the guide, not officially supported): `[mcp_servers.hummlist] url = "https://mcp.hummlist.com"` in `~/.codex/config.toml`, then `codex mcp login hummlist`. ChatGPT only on Business/Enterprise workspaces (docs); unverified on a live account.
- Privacy statement (quoted, do not edit): „Wir speichern zu jedem Schlüssel einen Namen, einen Hash, seine letzten vier Zeichen und den Zeitpunkt der letzten Nutzung. Endet ein Schlüssel, etwa weil du ihn widerrufst oder den Haushalt verlässt, löschen wir diese Angaben 30 Tage danach beim nächsten täglichen Aufräumen.“

## Driving it with Playwright

Preconditions:

- Seeded household „Familie Brandt“, signed in. For OAuth steps the browser context must be the one signed in to the app; the test registers an OAuth client with the official MCP SDK (`TestOAuthProvider`, `openAuthorization`, `callbackParams` in `e2e/tests/mcp-helpers.ts`). The Driving section may call the MCP endpoint over HTTP against the local stack only (`mcpUrl` = local `/functions/v1/mcp`), never production.
- Specs: `e2e/tests/mcp.spec.ts` (OAuth with consent, deny, sign-in on the way, access key lifecycle, cross-household, forged tokens, `counts`), `e2e/tests/mcp-consent-wait.spec.ts` (the done page while the client connects), `e2e/tests/integration-lock.spec.ts`; run with `scripts/verify.sh --only e2e -- tests/mcp.spec.ts tests/mcp-consent-wait.spec.ts`.

- **Open Zugänge.** `await openMore(page, 'Zugänge')`. URL `/more/access`.
- **API key (flag build only).** Reveal `page.getByRole('button', { name: 'API-Schlüssel erstellen' })` and click it, `typeInto(page.getByRole('textbox', { name: 'Name' }), 'Home Assistant')`, `page.getByRole('radio', { name: /^Lesen und schreiben/ }).click()`, `page.getByRole('button', { name: 'Erstellen', exact: true }).click()`. Observable: `page.getByText(/^fgp_[A-Za-z0-9_-]{43}$/)` visible, then after „Fertig“ the row text `…<4> · Lesen und schreiben · Erstellt am …`; supabase-js as the member reads the `personal_access_tokens` row with `kind` `api` and `scopes` `["read","write"]`.
- **Create a key.** `page.getByRole('button', { name: 'Token erstellen' }).click()`, `typeInto(page.getByRole('textbox', { name: 'Name' }), 'Claude')`, `page.getByRole('button', { name: 'Erstellen' }).click()`. Observable: `page.getByText(/^fgp_[A-Za-z0-9_-]{43}$/)` visible. Click `page.getByRole('button', { name: 'Fertig' })`: `page.getByText(/fgp_/)` count 0 (shown once).
- **Use it (HTTP, local only).** `connectWithToken(token, 'legacy' | 'modern')`, then `call(client, 'add_items', { items: [{ name: 'Gurken 3' }] })` (added: name „Gurken“, quantity „3“, category „Obst & Gemüse“), `call(client, 'list_items', { store: 'dm' })`, `call(client, 'list_stores')`. `list_items` returns `counts` `{ open, checkedLast24h }` for the whole list even with the `store` filter: `open` equals the household's open items, `checkedLast24h` the items ticked in the last 24 hours. In the app: `openTab(page, 'Liste')`, `itemRow(page, 'Gurken')` visible without reload.
- **Key row.** After use: `page.getByRole('group', { name: /^Claude …\S{4} · Erstellt am .* · Zuletzt benutzt / })`.
- **Revoke.** `page.getByRole('button', { name: 'Claude widerrufen' }).click()`, then `page.getByRole('button', { name: 'Widerrufen' }).click()`; the button `Claude widerrufen` has count 0 and a `tools/list` POST with the key returns 401 with `www-authenticate` containing `error="invalid_token"`.
- **Consent.** Open the authorization URL returned by the SDK flow (`openAuthorization(page, url, baseURL)`): the page shows the app name (`getByText('Claude (E2E)')`) and the email; `page.getByRole('button', { name: 'Erlauben' }).click()` returns the callback with `code`; `Ablehnen` returns `access_denied`. While the callback is pending the page shows `getByText('Fertig, du kannst zu Claude (E2E) zurückkehren.')` and `getByText('Verbunden', { exact: true })`, and the `Erlauben` button has count 0. A pending navigation holds Playwright's locators, so to look at that state stub `window.open` with `addInitScript` before the tap, as `mcp-consent-wait.spec.ts` does (the page opens the callback with target `_self`). Signed out: sign in on the way with `openEmailSignIn(page)`, `typeInto(getByRole('textbox', { name: 'E-Mail' }), …)`, `typeInto(getByRole('textbox', { name: 'Passwort' }), …)`, `getByRole('button', { name: 'Anmelden' }).last().click()`, then Erlauben.
- **Connected app row and details (job 80).** Back in Zugänge the row is one button named by title and subtitle: `getByRole('button', { name: /^Claude \(E2E\) Chrome · Linux · Verbunden am \S+ · Zuletzt aktiv \S+$/ })` (Playwright's Chromium on Linux); supabase-js as the member: `rpc('connected_app_details')` returns `[{ client_id, device: 'Chrome · Linux', last_used_at }]`. clicking that row opens the sheet: `getByText('Freigegeben auf Chrome · Linux')`; Escape closes it.
- **Connected apps and disconnect.** Back in Zugänge: `getByRole('button', { name: 'Claude (E2E) trennen' }).click()`, `getByRole('button', { name: 'Trennen', exact: true }).click()`; `getByText('Noch keine App verbunden.')` visible; the access token and refresh token are refused.
- **Retention (database).** Admin client: after revoking, the row's `revoked_at` is set; the row is deleted 30 days later by the daily job `purge_access_tokens` (call it as postgres after setting `revoked_at` back 31 days to prove deletion). Leaving the household (delete the `household_members` row) sets `revoked_at` for that user's keys in that household. unverified in a live run (read from the migration only).

## Gotchas

- The app screen title is „Zugänge“ in German; in English the app calls it "Access" and the site copy (landing) says "More › Connections". Do not take one for the other.
- Keys are shown once: copy the `fgp_…` value before „Fertig“. A second key with the same name makes the button „<Name> widerrufen“ ambiguous.
- A key works only while its owner is a member of that household; revoked keys vanish from the list immediately, the record is deleted after 30 days.
- The consent page is part of the Flutter web build (route `/oauth/consent`), reachable from an authorization link only; use the e2e helper flow.
- With the e2e build `INTEGRATION_LOCK` is on; with the server switch on, Zugänge shows a Premium card and „Pausiert: braucht Hummlist Premium“ under every key and app, and tool calls answer that the household needs Premium. The API section then adds the line „Die Hummlist-API gehört zu Hummlist Premium. Deine Schlüssel bleiben und funktionieren wieder, sobald dein Haushalt Premium hat.“ (key `api-premium`) and still offers new keys. Production has both off: that never shows. Do not describe it.
- The API section needs the `public-api` flag, which no local build gets from PostHog: build with `VH_DEFINES="FLAGS_ON=public-api" helpers/launch.sh` (SKILL.md, "Launch"). Creating a key and calling the API also need the server switch (job 75): `update public.app_switches set enabled = true where key = 'public_api'` on the local database (service role); with it off every API request answers 404 `not_found` and „Erstellen“ shows „Die API ist noch nicht freigeschaltet.“ Screenshots of job 73: `docs/screenshots/73/`.
- Tools answer in German (descriptions and error messages), e.g. unknown names come back as tool errors with the valid options. Results are JSON text.
- Alexa also shows under „Verbundene Apps“ as „Amazon Alexa“ (see the alexa map).
- unverified (third-party UIs): how ChatGPT and Claude present their connector screens.
