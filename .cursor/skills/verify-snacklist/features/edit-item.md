# Edit an item

Every item on the list has a name („Bezeichnung“ / "Name"), an optional brand („Marke“ / "Brand"), details („Eigenschaften“ / "Details", like "Größe 3" or "1,5 %") and a quantity („Menge“ / "Qty"). The row shows the quantity in bold in front of the name („6× Bananen“; a quantity of 1 is not shown), and under the name "Marke · Eigenschaften" when either is set. A hold or a right click on a row opens the edit sheet from the bottom; a swipe across a row does nothing (job 78). A plain tap does something else: it ticks the item off. The sheet edits fields, moves the item to another store or category and, in a household with several lists, to another list (group „Liste“ / "List", one button per list). Below that every open item's sheet has the checkbox „Ich bringe das“ / "I'll bring it": ticked, a field „Wie viel?“ / "How much?" (hint „z. B. 2“) appears, and other members' claims are listed under it (lists-and-claims). It has no delete since job 149: ticking an item off removes it.

## Sub-features

- `ed-row-details` the row's second line is "<Marke> · <Eigenschaften>" (either part alone, or no line when both are empty). Its accessible name is the name, then the details, then the quantity: „Milch Weihenstephan 2“, „Windeln Pampers · Größe 3“, „Milch 2 l“. A claim adds its line after them: „Butter Du bringst 2“ (driven 2026-11-09).
- `ed-open` the sheet (accessible group „Bearbeiten“ / "Edit", no title since job 149; the name field comes first) opens on a hold that stays put or a right click. The row stays where it was and nothing is written. A sideways drag or swipe opens nothing, ticks nothing and leaves the row in place (the swipe that edited since job 29c is gone since job 78). Screen readers get „Bearbeiten“ / "Edit" and „Löschen“ / "Delete" as actions on the row; the row's „Löschen“ is the app's only delete in the UI (the API, MCP and Siri delete too), with the snackbar „<name> gelöscht“ / "<name> deleted" and „Rückgängig“ / "Undo". When the same item is open on the list again by then, Undo shows that item as it is and adds no second one (job 64b, `put_item`).
- `ed-fields` four prefilled text fields: „Bezeichnung“ / "Name" (120 characters), „Marke“ / "Brand" (60; placeholder „ohne Marke“ / "no brand"), „Menge“ / "Qty" (40), „Eigenschaften“ / "Details" (120; placeholder „z. B. Bio, 1 l“ / "e.g. organic, 1 l"). Each label sits above its hex field; the text and placeholder sit in the middle of the hex, left-aligned, „Menge“ too (job 148). Fertig is disabled while the name is empty; Enter in any field saves like „Fertig“.
- `ed-steppers` next to „Menge“ two buttons, „Eins weniger“ / "One less" and „Eins mehr“ / "One more", change only the number and keep the unit: "2" gives "3", "2 l" gives "3 l", "1,5 l" gives "2,5 l", "500 g" gives "600 g" (grams and millilitres step by 100 from 100). An empty quantity counts as 1, so plus gives 2. „Eins weniger“ is disabled when one step down would go below one step: at 1, „1,5 l“, 100 g or 150 g. Both buttons are hidden when the quantity does not start with a number ("eine Packung"). They have no hover tooltip (job 122): on the web a tooltip moved the sheet, and a click into „Menge“ right after hovering a stepper lost its focus. Their names come from the icons, for screen readers too.
- `ed-chips` the store chip („Laden: <store>“ / "Store: <store>", for example „Laden: Ohne Laden“ / "Store: No store") and the category chip („Kategorie: <category>“ / "Category: <category>", for example „Kategorie: Kühlregal“ / "Category: Chilled") fold out their options inline: „Ohne Laden“ / "No store", the stores and „+ Neuer Laden“ (accessible name „Neuen Laden anlegen“ / "Add a new store", see stores-walk-order `sw-own-stores`; over five stores a search field „Läden durchsuchen“ / "Search stores" shows above them), or the categories. The chips carry no store or category icon in the edit sheet (job 149; the add sheet keeps them). A pick folds them back; the sheet grows and shrinks to its content. The edit sheet never shows the add sheet's automatic chips (muted, "A" mark): an item without a store (or whose store was deleted) shows „Ohne Laden“. An item without a category yet shows „Kategorie: automatisch“ / "Category: automatic", which is also its accessible name. A changed store or category is remembered for the next add of that item (see classifier and stores-walk-order).
- `ed-save` „Fertig“ / "Done" saves only the fields that changed, including the list and the claim. Without a change it just closes and writes nothing.
- `ed-rename-open` (job 104) „Fertig“ with the same name, brand and details as another open item on the same list (folded as an add compares them: case, spacing and umlauts, „MINERALWASSER“ or „Broetchen“ onto Brötchen) folds the edited item into that one instead of making a second row: the open item keeps its name, store and category, the quantities add up as Zusammenführen does (`public.merge_quantities`: none and none give 2, „6“ and „2“ give 8; a quantity typed in the same edit counts), and a snackbar says „Zusammengeführt: <Menge> <Name>“ / "Merged: …" with „Rückgängig“ / "Undo", which brings the edited item back under its old name. Nothing else merges (lead, Addendum 3): a rename to a synonym or another spelling (Semmeln while Brötchen is open) or to a name whose open item has a brand or details („Butter“ while „Butter“ Kerrygold is open) stays a second row, and once the server has the new name the list offers the duplicate hint, as an add does: „<Name> steht schon auf der Liste“ with „Zusammenführen“. A brand or details edit alone never offers the hint, but one that makes the item match another open one merges the same way. When another member's copy reached the server first (a rename made offline, also of a line typed offline, compared as the server splits it, or two phones renaming at once), the server refuses the rename, the list fetches that copy and folds the item into it the same way; the snackbar shows once the server merged. What was queued after the rename (a tick, a quantity) goes to that copy, as for an offline add that turned out to be on the list (job 114). A delete queued after the rename (the row's screen-reader action) drops the rename instead: the copy keeps its quantity and no snackbar shows. A second rename queued after it wins (the item takes that name, the partner's item stays; the first rename's brand and details are kept unless the second sets its own, and a line typed offline is split as an add would be), and when the copy is ticked before the merge arrives, the rename lands on its own. A refusal the list cannot match to a copy is sent once more, then shows „steht schon auf der Liste“. Only when the merged quantity would not fit (40 characters) does nothing merge: the snackbar says „<Name> steht schon auf der Liste“ / "<name> is already on the list" and nothing from that edit is saved (the old name, quantity and details stay). Its own name in another case („APFELSAFT“), a ticked copy and different details („Gerolsteiner“) stay a plain rename. The server refuses a rename onto another open item with the same name, brand and details for every writer (`items_rename_duplicate`, 23505). Driven 2026-11-06 on main 694114ee: `journeys/edit-item.mjs` (Apfelsaft onto Mineralwasser; Semmeln onto Brötchen only offered; Reis renamed „broetchen“ onto „4× Brötchen“ gave „Zusammengeführt: 5 Brötchen“).
- `ed-cancel` „Abbrechen“ / "Cancel", bottom left next to „Fertig“ (where „Löschen“ was until job 149; the top „Abbrechen“ is gone), drops every change, closes the sheet and writes nothing, without a snackbar. A store made in the sheet with „+ Neuer Laden“ is created right away and stays; only its pick is dropped.
- `ed-delete` gone since job 149: the sheet has no „Löschen“ / "Delete". An item leaves the list by ticking it off; the row's screen-reader action „Löschen“ remains (`ed-open`, tick-and-undo `tu-delete-undo`).
- `ed-parse` entries added by MCP or Siri (and the add sheet) are split into these fields by the server: "Windeln Pampers Größe 3" gives Windeln, Marke Pampers, Eigenschaften Größe 3, and Laden dm when the household has a store dm (no default stores since job 64; see the quick add feature).

## How to get to it (user POV)

- Press and hold a row, then let go without moving.
- Right-click a row (web and desktop).
- Screen reader: the row's custom action „Bearbeiten“ / "Edit".

## Driving it with Playwright

Preconditions:

- Signed in, on the list tab, an item without a brand on the list (for example `addItem(page, 'Milch')` from helpers, which types it, presses Enter and closes the sheet). Stores: the baseline „Familie Brandt“ has none, and the e2e household only the ones its spec passes to `signUpWithHousehold` (none by default). Add the stores a step picks first, as in `README.md` (Baseline); add dm by that name for the brand default (Pampers → dm).
- Existing coverage: `e2e/tests/edit-sheet.spec.ts` (right click, steppers, height, hold with Abbrechen, Abbrechen, touch variants in a phone browser) and `e2e/tests/item-details.spec.ts` (row second line). Run via `scripts/verify.sh --only e2e -- tests/edit-sheet.spec.ts`.
- Helpers: `openEdit(page, 'Milch')` right-clicks the row and waits for `editSheet(page)` (`getByRole('group', { name: 'Bearbeiten', exact: true })`); `editField(page, 'Marke')` is `editSheet(page).getByRole('textbox', { name: 'Marke' })`; `expectFieldValue(field, value)` reads a prefilled value; `pickInSheet(page, 'Laden' | 'Kategorie', '<option>')`; `saveEdit(page)` clicks „Fertig“ and waits for the sheet to go.

- **Open.** `await openEdit(page, 'Butter')`. Observable result: `editSheet(page)` is visible with the buttons Eins weniger, Eins mehr, `Laden: Ohne Laden`, `Kategorie: Kühlregal`, Abbrechen and Fertig; `expectFieldValue(editField(page, 'Bezeichnung'), 'Butter')`, and empty values for 'Marke', 'Menge', 'Eigenschaften'.
- **Edit and step.** `await typeInto(editField(page, 'Marke'), 'Weihenstephan')`, click `editSheet(page).getByRole('button', { name: 'Eins mehr' })` twice and `'Eins weniger'` once. Observable result: `expectFieldValue(editField(page, 'Menge'), '2')`.
- **Save.** `await saveEdit(page)`. Observable result: `itemRow(page, 'Butter')` has the accessible name `Butter Weihenstephan 2`, also after `page.reload()`; a read of the item through the API shows only brand, quantity and updated_at changed.
- **Move store or category.** First add dm, Lidl and EDEKA with `apiAs(...).rpc('add_store', …)` (README, Baseline). Unfold the store chip on Nudeln: the options are Ohne Laden, dm, Lidl, EDEKA and „Neuen Laden anlegen“. `await pickInSheet(page, 'Laden', 'dm')` (or `'Kategorie'` with a category name such as 'Getränke'), then `saveEdit(page)`. Observable result: the item sits under that store's divider (`storeDivider(page, 'dm')`, accessible name `dm, <n> Artikel`) or in that category; the API row has the new `store_id` / `category_id`.
- **Cancel.** Open, change a field or pick a store, click `editSheet(page).getByRole('button', { name: 'Abbrechen' })`. Observable result: sheet gone, no snackbar, row unchanged in the API; reopened, the sheet shows the old values (`Laden: Ohne Laden`). An open-then-„Fertig“ without changes also writes nothing.
- **Delete.** Not drivable on web: the only in-app delete is the row's screen-reader action „Löschen“, and Flutter web does not expose custom semantics actions. Specs delete through the API (`deleteItem(api, page, item)` in `e2e/tests/catalog.ts`); the action and its snackbar are covered by the widget test „screen readers get edit and delete as actions“ in `app/test/list/list_screen_test.dart`.
- **Rename onto an open item.** `node journeys/edit-item.mjs <dir>` on a freshly seeded `demo-familie` renames Apfelsaft to Mineralwasser (`--to MINERALWASSER` for the case). Observable result: one open Mineralwasser (the same id as before) with quantity 2 in the API, the group `Zusammengeführt: 2 Mineralwasser`; its „Rückgängig“ brings Apfelsaft back. `--to Semmeln --onto Brötchen` proves a synonym does not merge: two open rows and the hint „Brötchen steht schon auf der Liste“. The branch follows the fold only, so a typo for `--to` takes the hint path too. A synonym run leaves Semmeln open: reseed before the next run. Unit and widget tests: `app/test/list/list_cubit_test.dart` and `dedupe_hint_test.dart` („a rename onto an open item (job 104)“); server: `supabase/tests/rename_open_duplicate.test.sql`. Offline and two phones: `e2e/tests/rename-onto-open.spec.ts`; the sync fuzz (`app/test/fuzz`) fails on two open rows with one name and on a rename kept apart from its open copy.
- **Hold.** With the mouse press on the row, wait 450 ms, release; on a touch page `fingerHold(page, itemRow(page, 'Zahnpasta'))`. Observable result: `editSheet(page)` is visible and the row is still in the list.

## Gotchas

- A tap or click on a row ticks the item. Open the sheet with a right click (`openEdit`) or a hold, never a left click.
- A press and release on a row within 200 ms is a click to the engine, so a drag that is meant not to tick must last longer (iphone.spec.ts lifts its swipe after 300 ms).
- Flutter web fills a text field's input only while it is focused, so a prefilled value reads empty until the field is clicked; use `expectFieldValue`.
- The chip and its option can show the same text ("dm"); only the chip's accessible name has the prefix „Laden: “ / „Kategorie: “. Pick options with `getByRole('button', { name: '<option>', exact: true })` after unfolding the chip.
- Use `typeInto` for typing, as umlauts are dropped by synthetic key events.
- A row that has just arrived from the partner shows „Neu“ / "New" in its screen-reader name for a few seconds (the row's accessible name gains a line); match rows with `itemRow`, which ignores trailing text.
- Items under „Zuletzt verwendet“ cannot be edited: a hold or right click does nothing there, only a tap puts them back.
- A hold on any row, sorted or still being classified, opens the sheet as soon as the hold completes (about 300 ms), while the pointer is still down; nothing on the list drags (job 78).
- Making a store from the edit sheet has no e2e spec (`e2e/tests/stores-add.spec.ts` uses the add sheet); `app/test/list/store_picker_test.dart` covers the picker.
- The sheet's exact height (hugging its content, every button at least 44 px, „Fertig“ and „Abbrechen“ 52 px) is pinned by `expectHugsContent` in the spec; do not assert pixel sizes in other recipes.
- The iPhone (WebKit) touch variant lives in `e2e/tests/iphone.spec.ts` ("a finger swipe across a row opens nothing and moves nothing; a hold edits; Abbrechen in it closes").
