# Stores

Every store of the household is a section of the list: a divider "<Store>, N Artikel" (since job 57 the store's full name sits in a hex badge, `StoreBadge`, with a cobalt rule for every store and no retailer colours; Liste → Anpassen shows the same badge), then the items tagged to that store in the store's walking order. Items without a store sit in a last section, "Ohne Laden", in the household's route order. There is no store view (job 16): an item gets its store in the edit sheet or from the add sheet's store chip as it is added; nothing on the list drags (job 78). Liste → "Anpassen" (the list header's button, `list-edit`, route `/edit`; job 78, before Mehr → Läden) lists the stores in list order and "Ohne Laden" pinned last; a drag on a handle reorders them, a tap opens a store's details (rename, walking order, categories), the trash deletes one, and "Laden hinzufügen" adds one (jobs 58, 78). The store options of the add and edit sheets end in "+ Neuer Laden" too: the typed name becomes a store of the household and is picked in one step. The household remembers where each item was put, so a later re-add lands in that store again. Each store's category order is editable on its details, which a hold or right click on its divider also opens.

## Sub-features

- `st-sections` shows one divider per store with open items, in store order, and "Ohne Laden" last while it has items. A store without items does not show (no divider, no "0 Artikel"). The list without any item shows only the empty state.
- `st-order` sorts a store's section by that store's category order (Lidl: "Brot & Backwaren" before "Obst & Gemüse"; Edeka: "Fleisch/Wurst/Fisch" before "Kühlregal"), and "Ohne Laden" by the route.
- `st-memory` puts a re-added item back in the store it was last tagged to.
- `st-tick-no-tag` leaves an untagged item untagged when it is ticked; nothing is remembered.
- `st-sheet` sets the store in the edit sheet (store chip, key `chip-store`); "Ohne Laden" (`store-option-none`) clears the tag and the memory.
- `st-layout` opens the store's details (`store-details`, route `/edit/<id>`, title = the store's name) from the stores screen or with a hold or right click on the store divider (job 78; no divider menu any more). On top a pill with the store's badge and "Tippen zum Umbenennen" (`store-rename`, label "<Store> umbenennen"); then the categories in walking order, each with its step number, a trash (not "Sonstiges") and a drag handle; a tap renames a category (`features/categories.md`). The "gibt es bei" switches are gone; a reorder keeps the stored hidden flags. Every change saves at once. A store deleted on another device sends the screen back to the stores.
- `st-layout-reorder` reorders a store's categories by dragging their handles ("<category> verschieben").
- `st-add-chip` sets the store of a new item with the add sheet's store chip and remembers it (`features/quick-add.md`, `qa-chips`).
- `st-stores-screen` lists the stores under Liste → Anpassen (key `stores-screen`, title "Läden", rows `store-row-<id>` labelled with the store's name, a trash `store-delete-<id>` "<Store> löschen" and a handle "<Store> verschieben"); a drag on a handle reorders them, a tap on a row opens its details. Last, pinned and flat (no edge, muted text, no trash or handle), "Ohne Laden" with "Kategorien für Artikel ohne Laden" (`store-row-none`) opens the route order. Bottom right "Laden hinzufügen" (`store-add`). The store-name note stands only in onboarding now (job 78).
- `st-own-picker` makes a store from the store options (add or edit sheet): "+ Neuer Laden" (`store-option-new`) turns into a focused field (`store-new-field`, check `store-new-confirm`, close `store-new-cancel`); Enter or the check creates the store and picks it, announced "<Store> angelegt und ausgewählt"; Escape or the close button cancels and focus goes back to the + row. A name the household has, in any case or spacing, picks that store instead (no duplicate). Names are trimmed, spaces collapsed, at most 40 characters.
- `st-own-search` shows a search field (`store-search`) above the options once the household has more than five stores; it filters by name, and Enter picks the store of that name or opens the new-store field with the text.
- `st-own-layout` gives a new store the household's route order with every category (a store named dm, Lidl or EDEKA, in any case, becomes that chain with its researched order instead, unless the household has that chain already), editable on its details like a preset store's; a category added later joins it.
- `st-own-manage` adds a store under Liste → Anpassen ("Laden hinzufügen", `store-add`: a dialog with the field "Name des Ladens", `name-dialog-field`, and "Laden anlegen", `name-dialog-confirm`; a name the household has picks nothing new; refused or offline the dialog stays open), renames one on its details (`store-rename`: the same dialog prefilled, "Speichern"; a name another store has keeps the dialog open and says "Einen Laden „…“ gibt es schon.") and deletes one with its row's trash (`store-delete-<id>`, a dialog naming how many open items move to "Ohne Laden", `store-delete-confirm`): its items, open and bought, have no store afterwards. Renaming a preset store to another name ("dm" → "Rossmann") clears its seed key, so dm's brand defaults no longer pick it.
- `st-own-empty` shows "Noch keine Läden. …" (`stores-empty`), "Ohne Laden" and the add button on Liste → Anpassen for a household without stores ("Überspringen" in onboarding, or no store picked).
- `st-own-offline` refuses adding, renaming and deleting offline with "Läden lassen sich nur mit Verbindung anlegen, umbenennen oder löschen."; an existing store is still picked by name.
- `st-store-order` reorders the stores on the stores screen (Liste → Anpassen), not on the list (job 78).

## How to get to it (user POV)

- Scroll the list: each store is a section with its own divider.
- Hold an item (or right-click it), then pick a store under "Laden".
- Hold a store's divider (or right-click it): its details open.
- On the list, tap "Anpassen" top right; tap a store, or drag its handle.
- In the add or edit sheet, open "Laden", tap "+ Neuer Laden", type a name and press Enter.
- Under Liste → Anpassen, tap "Laden hinzufügen" or a store's trash; tap a store, then its name on top, to rename it.

- Baseline from `features/README.md` with the chain stores dm, Lidl and Edeka, added as in `features/README.md` (Baseline); peter signed in on the list. `fg up --fresh` if earlier runs tagged these items or changed a store layout: tags, memory and layouts survive `fg up`.

Tap `--key list-hint-dismiss` if the card shows, so all sections fit.

The store query used below: `S="select i.name, s.name as store, c.name as category from items i left join stores s on s.id = i.store_id join categories c on c.id = i.category_id where i.status = 'active' order by 1"`.

## Gotchas

- The store chips "Alle/dm/Lidl/Edeka", store views, the dm "… anzeigen" button and the "gibt es bei" switches are gone (job 16). `fg tap --text dm` now hits the dm divider's name or the edit sheet's store option, not a chip.
- With the edit sheet's store options open, the store names show twice (the option and the divider behind the sheet). Tap options by key (`store-option-<id>`).
- A new item takes the store memory holds for its name, from the app, MCP and Siri alike (`features/edit-item.md`). Earlier runs' memory therefore puts the test items into stores at once; start from `fg up --fresh` when "Ohne Laden, 6 Artikel" matters.
- Store memory and layouts persist across `fg up`. `fg up --fresh` restores them.
- `fg back` on the list screen and on the More list closes the Linux app. Use it only on pushed screens (a store's details, the stores, Zugänge, Konto, dialogs).
- The `hidden` flags in `store_category_order` stay in the database but change nothing in the app.
- MCP finds own stores by name (`features/mcp-access.md`); Siri, the voice endpoint and Alexa never name a store, so an own store comes to them through memory only.
- `classifier.md` covers categories; `categories.md` covers renaming, adding and deleting them, which also changes every store's order; `list-walk-order.md` covers the hold, folding and the divider hold.
